# Untangle: decision log (2026-11-25)

The question behind every change: **should these pieces change together?** The result is in [ARCHITECTURE.md](../ARCHITECTURE.md). This page records what changed, and the special cases that remain on purpose. The commits run from `49babdc` to `2ef3112`.

## Bugs fixed on the way

Each fix has its own commit; most also have a test.

- **The watchdog was unarmed during Enter.** The lease deadline was published after the effect that hides the Mac's cursor.
- **Pairing could finish after the code expired.** A client could also hold it open by sending one byte at a time. Pairing now runs against one deadline.
- **Screen view: reopening the window let the old window's threads take over the new one.** Also, `hop view` never exited when its connection failed.
- **Upgrading the PC replaced the service's key with the console's**, which broke pairing.
- **The Mac app kept using the PC's first address** after the link had followed the PC to a new one.
- **The Mac ignored Ctrl+C and `kill` until Accessibility was granted.** Quitting now gives the Mac its input back first.
- **Mouse buttons 8 and up shared one bit.**
- **⌃L locked the PC again on every key repeat.**
- **Two stored files shared one temporary file.**
- **A pairing beside the service could undo an Unpair that happened while it ran.**
- **Two first pairings at once could each create a Mac key.**
- **A timer race could delay a heartbeat or a retransmit.**
- **The agent's command line read option values as commands.**

## Structure

- **One PC-side session acceptor for input and video** (`responder.rs`): replay-safe promotion, address following, and the unknown-session hint.
- **Wire and video types:** wire messages live in `wire.rs`, and an encoded frame is one type, `video::Encoded`. A test pins every message to the bytes Hop 1.0.0 sends.
- **The video client** keeps its own request schedule. Each viewer owns its window and stop flag.
- **The session** has one step function, wakes the timer only for sooner work, and has a lock-free `lease_expired`.
- **Pairing:** `PairError` is typed, there is one deadline, and the lock and generation token live in `store.rs`. The menu labels each machine quotes from the other are in `ui.rs`.
- **The Mac app:**
  - `pc.rs` is a library, and the commands return errors to `main`.
  - `Live::connect` builds every session, and `Controller::switch` serves both the hotkey and the menu.
  - One quit path runs from launch. The app's start-up lives in `macos.rs`, and the network helpers in `net.rs`.
- **The PC agent:**
  - `video.rs` owns the video process, with its command line built and parsed in one place.
  - `backoff.rs` is shared by both supervisors, and `lock.rs` holds the ⌃L rule.
  - The command line is parsed per command and tested. A caught mode covers swallow and selftest.
- **Packaging:** `packaging/common.sh` names the release once.

## Special cases kept on purpose

| Special case | The constraint behind it |
|---|---|
| `Want.complete` and `Want.lost` stay on the wire, unused | Hop 1.0.0 sends them, and there is no protocol version |
| The service polls every second; `sc` shell-outs; the installer script as it is | Changing them needs a run on a real Windows PC; they can't be tested from the Mac |
| ⌃L matches L by its key position, not the keyboard layout's letter | Verified working on a real PC; the layout premise is unverified |
| Mouse Keys is restored only on a clean stop | A forced kill runs no cleanup |
| `layout.rs`'s per-side edge arithmetic stays as it is | The crossing bands differ by a fraction of a pixel; unifying them needs a check on real displays |
| A damaged pairing record reads as "not paired" | Writes are atomic, and the user can pair again |
| A failed settings save is not reported | It only loses that choice at the next launch |
| The display layout is polled every 2 s | Cheap, and on the same thread as the Secure Input poll, which has no notification |
| Fixed waits in `hop drive` and the loopback rig | Developer tools only |
| Non-Windows agents default to `--dry-run` | Only Windows can inject input |
| The viewer opens at a provisional size | It shows "connecting…" at once; the decoder's picture size then reshapes it |
| The first-run pairing dialog reopens at each launch until the first pairing | A Mac that has never paired has nothing else to do; after one pairing it opens only when asked |
